# P1 검증 실행 안내 (노트북, Windows)

P1 은 물 한 가지(또는 주어진 밀도 분포)의 유동을 푸는 단계입니다. 자유수면과 원통은 아직 없습니다.
검증 시험 4종(1-A ~ 1-D)의 조건과 통과 기준은 `docs/design/03_verification_plan.md` §1.1 에 **코드 작성 전에 고정**되어 있습니다 (커밋 35a77ac).

## 1. 최신 코드 받기와 빌드

GitHub Desktop 에서 **Fetch origin → Pull origin** 후, "x64 Native Tools Command Prompt for VS 2026" 에서:

```bat
cd /d "%USERPROFILE%\Documents\GitHub\test"
cmake --preset windows-x64-release
cmake --build --preset windows-x64-release
ctest --preset windows-x64-release
```

`ctest` 는 빠른 시험만 돌립니다 (단위 시험 + 검증 시험 축소판). 축소판은 **동작 확인용이며 판정이 아닙니다.**

## 2. 전체 검증 실행 (판정)

```bat
out\build\windows-x64-release\hcw_verify.exe all
```

- 시험별로 실행할 수도 있습니다: `1A`, `1A-a`, `1A-b`, `1B`, `1C`, `1D`
- 가장 고운 격자(256×256) 때문에 **수십 분 이상** 걸릴 수 있습니다. 창을 닫지 마세요.
- 결과는 화면과 `results\verification\P1\<시험>\<시각>\report.txt` 에 저장됩니다.

## 3. 결과 읽는 법

| 표시 | 뜻 |
|---|---|
| `[PASS]` / `[FAIL]` | 고정된 기준 하나하나의 통과 여부 |
| `p_obs` | 관측 수렴 차수. 격자를 절반으로 줄일 때 오차가 줄어드는 정도 (2 에 가까우면 설계대로) |
| `verdict : VERIFIED` | 모든 기준 통과 |
| `verdict : FAILED_CRITERIA` | 기준 하나 이상 불통과 — 결과를 그대로 기록하고 원인을 분석합니다 |
| `verdict : FAILED_SOLVER` | 압력 방정식이 허용치까지 수렴하지 못함 |
| `QUICK_CHECK_ONLY` | 축소판 실행. 판정 아님 |

`report.txt` 의 첫 부분에 코드 커밋, 컴파일러, 기기 이름이 기록됩니다. 판정 기록(`validation/records/`)은 이 파일을 근거로 작성합니다.

## 4. 정식 판정 전에는 빌드 폴더를 지우고 새로 빌드 (2026-10-22 추가)

```bat
rmdir /s /q out\build\windows-x64-release
cmake --preset windows-x64-release
cmake --build --preset windows-x64-release
```

- 이유: 한국어 Visual Studio 의 컴파일러는 헤더 의존 정보(`/showIncludes`)를 한국어로 출력합니다.
  - 빌드 폴더를 처음 만들 때 CMake 가 기록한 문구의 인코딩이 실제 출력과 어긋나면, Ninja 가 헤더 의존성을 기록하지 못합니다.
  - 그러면 헤더만 바뀐 경우 그 헤더를 쓰는 파일이 다시 컴파일되지 않습니다. 이전 코드와 새 코드가 섞인 프로그램이 만들어질 수 있습니다.
- 2026-10-22 노트북에서 실제로 확인했습니다. 빌드 폴더를 새로 만든 뒤에는 의존성이 정상 기록되는 것도 확인했습니다.
- 정식 판정은 반드시 새로 만든 빌드 폴더에서, 수정 없는 커밋으로 실행합니다.

## 5. 여러 CPU 코어로 실행하기 (선택, 2026-10-23 추가)

기본은 지금까지처럼 **1 스레드**입니다. 켜려면 `--threads <수>` 를 붙이거나 환경 변수 `HCW_THREADS` 를 둡니다.

```bat
out\build\windows-x64-release\hcw_verify.exe 2D --threads 4
```

```bat
set HCW_THREADS=4
out\build\windows-x64-release\hcw_verify.exe 2D
```

- 스레드 수는 `report.txt` 머리의 `threads  :` 줄과 `run_meta.txt` 의 `solver_threads` 에 기록됩니다.
- **결과는 스레드 수와 상관없이 1 스레드와 마지막 자리까지 같습니다.** 반복 횟수도 같습니다. 그래서 1 스레드로 낸 이전 결과, 노트북·워크스테이션 비교와 그대로 맞춰 볼 수 있습니다.
- 권장 스레드 수: 그 컴퓨터의 **실제 코어 수** 이하 (노트북 4, 워크스테이션 12 이하). 노트북의 8 "하드웨어 스레드" 는 코어 4 개를 둘씩 나눠 쓰는 것이라 8 로 해도 빨라지지 않고 오히려 느렸습니다.
- 여러 시험을 동시에 따로 돌릴 때는 **모든 실행의 스레드 수 합이 코어 수를 넘지 않게** 하세요. 넘으면 스레드들이 서로 기다리느라 크게 느려집니다 (결과는 그래도 같습니다).

### 5.1 어떻게 결과가 같게 유지되나

컴퓨터의 실수 계산은 더하는 순서가 바뀌면 마지막 자리가 달라질 수 있습니다. 그래서 순서를 하나도 바꾸지 않는 일만 나눴습니다.

| 계산 | 다중 스레드 처리 |
|---|---|
| 행렬–벡터 곱, 벡터 갱신, 운동량 우변(면마다), VOF 재구성·플럭스(셀마다) | 칸마다 따로 계산되므로 칸 묶음을 스레드에 나눔. 각 칸의 식·순서는 그대로 |
| 내적·노름 (여러 값을 더해 하나로 만드는 계산) | **나누지 않음.** 한 스레드가 원래 순서대로 더함. 다만 ‖r‖² 하나는 전처리와 동시에 남는 스레드에서 계산 |
| IC(0) 전처리의 삼각 풀이 (앞 칸 결과를 써야 하는 순차 계산) | 칸 순서(자연 순서)를 **바꾸지 않고** 파이프라인으로 나눔: z 방향을 구간으로 나눠 스레드마다 맡고, 앞 구간이 같은 r 열을 끝내면 다음 구간이 시작. 색칠(colouring)처럼 순서를 바꾸는 방법은 반복 횟수와 결과가 바뀌므로 쓰지 않음. 행렬 모양이 이 순서로 안 맞으면 자동으로 1 스레드 풀이 |
| 물 체적 합 등 검사용 합 | 나누지 않음 |

같은 변경에서 1 스레드도 빨라졌습니다: PLIC 다각형과 압력 행렬 조립이 계산마다 메모리를 새로 잡던 것을 고정 크기로 바꿨습니다 (계산식은 그대로라 결과도 같음).

### 5.2 측정 (노트북 i7-1165G7, 4 코어, 2026-10-23, 커밋 e4a3f5d, 새 빌드 폴더)

비교 기준 "이전" 은 바로 앞 커밋 a931577 의 프로그램입니다. "같음" 은 시각·빌드·스레드 줄을 뺀 출력 전체(모든 지표, 반복 횟수, 판정)가 글자 하나까지 같다는 뜻입니다.

| 시험 | 이전 (1 스레드) | 새 코드 1 스레드 | 새 코드 4 스레드 | 이전 대비 | 출력 |
|---|---|---|---|---|---|
| 1C --quick | 0.1 초 | 0.1 초 | 0.1 초 | — (격자가 작아 나누지 않음) | 같음 |
| 2D --quick | 2.9 초 | 2.8 초 | 2.8 초 | — (격자가 작아 나누지 않음) | 같음 |
| 2B 전체 (중간 규모, 최대 256×512) | 172 초 | 47 초 | 37 초 | **4.6 배** | 같음 (VERIFIED) |
| 2D 전체 (a/dx = 16, 32) | 475 초 | 425 초 | 261 초 | **1.8 배** | 같음 (VERIFIED) |

- 축소판 17 개 시험 모두 (이전 / 새 1 스레드 / 새 4 스레드) 출력이 같았습니다. ctest 38/38 통과.
- 2D 의 a/dx=32 만 보면 442 초 → 234 초입니다. "65 분" 은 이전 코드(1bf8393, 2026-10-23 새벽) 기준이고, 지금 코드(방식 B 대류)는 1 스레드로도 약 8 분입니다.
- 2D 에서 4 코어로 1.8 배에 그치는 이유: 압력 해법의 내적 2 개는 순서를 지키려고 한 스레드가 계산하고, 노트북은 여러 코어가 동시에 일하면 클럭이 내려갑니다. 워크스테이션(12 코어)은 아직 측정하지 않았습니다. 처음 실행할 때 `--threads 1` 과 `--threads 6`, `--threads 12` 로 같은 시험을 돌려 시간을 비교하고, 출력이 같은지 확인해 주세요.
- 압축성 공기 시험(2-A, 2-C, 2-F 의 점성 암시 운동량 풀이, ILU(0)+BiCGSTAB)은 행렬–벡터 곱만 나눠져 있어 덜 빨라집니다. ILU(0) 삼각 풀이도 같은 파이프라인 방식으로 나눌 수 있지만 아직 하지 않았습니다.
